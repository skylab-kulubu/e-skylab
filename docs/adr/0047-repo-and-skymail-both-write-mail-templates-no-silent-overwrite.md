# The repo and SkyMail both write Mail templates, and neither silently overwrites the other

The Mail templates in `skymail-frontend/emails/` reach SkyMail through a Template seed, and SkyMail's editor writes the same templates. Both stay writers: a design fix that touches every template at once — the dark theme and the logo on 2026-09-22 — can only come from the repo, and wording must stay editable without a release (ADR-0045). So the conflict is made visible instead of silent. A seed updates a template only when no operator has changed it since the last seed, and otherwise refuses unless forced; forcing is safe, because the operator's work remains a Mail template version that can be restored. The same holds the other way: an operator publishing a draft started before a newer version was published sees both side by side and chooses, rather than quietly reverting it.

Rejected: the repo as the only writer (every wording change becomes a release again); SkyMail as the only writer, with the repo seeding each template once (design fixes stop reaching live mail); a seed that overwrites unconditionally, which is how SkyMail behaved until now and how Postmark's CLI behaves (an operator's change vanishes on the next seed with nothing said); per-field exceptions such as leaving only the subject alone, which stand only until versioning exists.
