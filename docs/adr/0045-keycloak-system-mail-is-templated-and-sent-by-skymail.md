# Keycloak system e-mails are templated and sent by SkyMail, with Keycloak SMTP as fallback

Keycloak sends verification, password-reset, personal e-mail confirmation and YTÜ-link e-mails with its own SMTP and stock templates, so every wording change is a Keycloak release behind the physical WebAuthn evidence gate, and the club's mail lives in two places. SkyMail is the club's mail domain (templates, lists, sending) and core already sends welcome and certificate mails through `POST /v1/mail_tasks/single` with a service-account token. We decided that Keycloak system mails are templated in SkyMail (system templates addressed by a stable key, protected from archiving) and sent by SkyMail through a small Keycloak e-mail provider in the SKY LAB SPI; SkyMail processes single sends immediately and retries transient failures; if SkyMail is unreachable the provider falls back to Keycloak's SMTP with stock templates so security mails never wait on SkyMail.

Rejected: a Keycloakify e-mail theme as the only path (branding in code, release per wording change); RabbitMQ event-driven mail (no consumer exists and the listener is not realm-managed); a second mail sender inside Account center.
