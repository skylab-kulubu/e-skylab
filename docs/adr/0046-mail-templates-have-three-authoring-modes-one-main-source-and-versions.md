# Mail templates are written in three authoring modes; one main source is sent, and every change is a version

SkyMail's editor compiles React Email JSX in the browser with `@babel/standalone`. The research for the Next.js rewrite recommended dropping it: Babel's own docs discourage it in production, it is most of a ~3 MB bundle, and its empty preview blanked seeded templates until the save guard of 2026-09-22. We keep it, and add two more Authoring modes — Visual, our own block editor on tiptap as Skyforms has, and raw HTML — because everything in a Mail template must be editable in SkyMail without a release (ADR-0045), and HTML is the escape hatch mail tools are expected to offer. The modes coexist: a Mail template may hold a source in each, and exactly one Main source is rendered and sent; making another source main is a deliberate choice that never discards the others. Every change writes a Mail template version. An operator's version is a draft until published, so a half-finished edit never reaches recipients; any version can be compared with another as rendered mail and restored. The only edits SkyMail refuses are those that drop a Required variable.

Rejected: removing the in-browser compiler (takes JSX editing away from the people who write it); SendGrid's one-way switch from its design editor to its code editor (loses the source you switched away from); saving straight to live mail (history restores the template, not the mail already sent with it); a bought or embedded editor (Unlayer, Stripo, Beefree and Topol load the editor itself from their CDN, whatever licence their npm loader carries).
