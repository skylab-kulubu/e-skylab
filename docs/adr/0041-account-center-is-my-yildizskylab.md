# Account center lives at my.yildizskylab.com; sky-app opens it in-product

The branded account surface (CONTEXT **Account center**) is a standalone Next.js product at `https://my.yildizskylab.com`. Club consoles and sky-app send the User there for password, sessions, passkeys/OTP, IdP profile, and self-delete. On sky-app this follows Meta Accounts Center: one web product at `my.`, first-party in-app WebView, short-lived `handoff?code=` (not the Keycloak access token in the URL), then httpOnly session cookie on `my.` (BFF). `my.` uses a version-pinned server adapter for read-oriented Keycloak account data; password, passkey, and OTP mutations use Keycloak Application Initiated Actions with step-up authentication and return to `my.`. Those sensitive steps may render the SKY LAB Keycloak theme on `e.` inside the same WebView/browser flow, but Keycloak Account Console is not the product and `e.` is not a stopgap entry point. Self-delete blocks access immediately and completes anonymization/detachment asynchronously; operational history and issued certificates remain without an active account link. The v1 product has no “applications you use” screen. sky-app account entry ships only when `my.` is production-ready. Rejected: waffle as the account UI; password screens in superadmin; a Keycloak theme on `e.` as the product; fully native duplicate account UI; a blanket hard delete through the current core user-delete path; `account.yildizskylab.com`.

Geriye kalan tek AIA, YTÜ hesabı bağlama (`kc_action=idp_link`) akışıdır._
