# Account center owns every self-service account action; Keycloak is extended by SPI, never forked or hopped to

ADR 0041 shipped v1 with Keycloak Application Initiated Actions on `e.` for password, passkey and OTP changes and a read-only profile. The product owner wants the Meta Accounts Center feel: one origin, no hop between sites. We decided that `https://my.yildizskylab.com` renders **every** self-service account action itself and that Keycloak stays the identity store but is extended with a SKY LAB Keycloak SPI (`sky-account` REST) that performs credential and e-mail mutations for `my.`: password change with current-password check and realm password policy, TOTP setup, WebAuthn registration, credential deletion, e-mail change and primary selection. Sensitive actions require a `my.`-side step-up (**Sudo mode**: password, passkey or TOTP, valid five minutes); only a person with none of these is sent to Microsoft re-authentication. `e.` is therefore visible only for the initial login, the YTÜ Microsoft link, and that fallback. The v1 exclusions are retracted: club profile (core), profile picture, groups/roles as a human-language **Permissions view**, and the person's own phone (read-only until phone verification exists) are shown in `my.`.

Consequences: the password now transits the `my.` BFF, so Account center is operated as identity-critical infrastructure like Keycloak; the WebAuthn passwordless RP ID becomes `yildizskylab.com` so passkeys work on every SKY LAB origin, and passkeys registered against `e.yildizskylab.com` must be re-registered; the `my.` BFF token gains the `core` audience but carries no core roles, so a leaked token can only reach the person's own endpoints; `GET /v1/users/me` returns the person's own phone, amending the "User phone" lock; Keycloak permissions are not conditional, so "verified YTÜ account has locked name and school e-mail" is enforced by `my.`.

Rejected: forking Keycloak (every security patch becomes a merge); Keycloak Admin REST through a service account (realm-admin power inside a user-facing app, no way to verify the current password); embedding `e.` pages in an iframe (Keycloak forbids framing login pages, password managers and WebAuthn are unreliable in frames, and it trains people to type credentials under the wrong address bar); keeping the AIA hop permanently with a matching theme (Google model) — accepted only as the transitional state until the SPI ships.
